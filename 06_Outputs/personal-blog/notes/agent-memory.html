Agent Memory

长期记忆系统

记忆不是为了让 Agent 自动乱改自身，而是让它从长期交互中积累经验，形成稳定的用户理解、任务连续性和协作能力。

为什么需要记忆

语音交互天然是连续、情境化、个性化的。如果系统没有长期记忆，每一轮只能依赖当前文本和短期 chat history，很难形成可信的长期协作关系。

记忆类型

  • Semantic memory：稳定事实、用户偏好、长期项目状态。
  • Episodic memory：发生过的事件、会话、阶段性任务。
  • Procedural memory：流程、操作习惯、工程经验。
  • Reflective memory：系统对交互模式和失败经验的总结。

目标闭环

ASR final → MemoryManager 检索相关记忆 → PipelineContext 注入
→ Agent 生成回复 → 后台提取新记忆 → MemoryStore 写入或更新

MVP

第一阶段目标是支持显式记忆、主动回忆、自动注入、用户隔离、基础遗忘和后端调试。第二阶段再加入可视化面板，展示本轮检索到的 memory、score、type 和来源。
