X-Talk 系统架构分析

核心问题

X-Talk 是一个开源的全双工级联式语音对话系统框架，主要解决：

  • 亚秒级端到端延迟
  • 多异构组件协调
  • 灵活的模型集成与热替换

整体架构

核心架构详解

1. API 入口层 (api.py → Xtalk 类)

api.py

Xtalk 是整个系统的高级接口：

方法 作用
from_config(path) 从 JSON 配置创建 Xtalk 实例
connect(websocket) 接受 WebSocket 连接并启动会话
register_model_search_spec(slot, spec) 注册自定义模型搜索路径
embed_text(session_id, text) 向指定会话注入文本嵌入
add_agent_tools(tools) 给 Agent 添加自定义工具

模型注册表 (MODEL_REGISTRY): 通过 slot name → import specs 映射，实现动态模型发现与加载。

2. 事件驱动核心 (serving/)

EventBus

event_bus.py

  • 基于 asyncio.create_task 的异步事件分发
  • 支持优先级排序、错误隔离、事件历史追踪
  • 所有 Manager 通过 subscribe / publish 松耦合通信
事件类型 (~50+ 种)

events.py

主要事件类别：

类别 关键事件 说明
Audio AudioFrameReceived, EnhancedAudioFrameReceived 音频帧输入
VAD VADSpeechStart, VADSpeechEnd 语音活动检测
ASR ASRResultPartial, ASRResultFinal, ASRStableSegmentReady 语音识别结果
LLM LLMAgentResponseUpdate, LLMAgentResponseFinish, LLMFirstChunk LLM 生成
TTS TTSStarted, TTSChunkGenerated, TTSFinished, TTSVoiceChange 语音合成
Turn TurnTTSStartRequested, TurnLLMAgentStartRequested 等 轮次协调
Metrics LatencyMetricsUpdated 延迟监控
Speaker SpeakerRecognized 说话人识别
Caption CaptionUpdated, ThoughtUpdated 音频描述/思维链
Retrieval RetrievalUpdated, TextForEmbeddingReady RAG 检索
Switch TTSModelSwitchRequested, LLMModelSwitchRequested 运行时模型切换
Manager 基类与事件绑定

interfaces.py

  • Manager = EventListenerMixin + ShutdownMixin
  • 使用 @Manager.event_handler(EventType) 装饰器声明式绑定事件处理
  • 通过 EventListenerMeta 元类在实例化时自动注册到 EventBus
  • 支持运行时 subscribe_event / unsubscribe_event 进行事件路由重写

3. Service 层

service.py

  • 每个 WebSocket 会话 = 一个 Service 实例
  • Service 创建 EventBus + InputGateway + OutputGateway + 12 个 Manager
  • DefaultService 预注册了全部 12 个 Manager
  • ServiceManager 管理多个并发会话生命周期
  • 支持 Prototype 模式 (clone) 复制会话

4. Pipeline 层 (模型容器)

default.py

DefaultPipeline 是一个 dataclass，作为所有模型实例的容器：

字段 模型类型 必需
asr_model ASR ✅
llm_agent Agent ✅
tts_model TTS ✅
captioner_model Captioner ❌
punt_restorer_model PuntRestorer ❌
caption_rewriter Rewriter ❌
thought_rewriter Rewriter ❌
vad_model VAD ❌
enhancer_model SpeechEnhancer ❌
speaker_encoder SpeakerEncoder ❌
_speed_controller SpeechSpeedController ❌
embeddings_model Embeddings ❌
  • 通过 clone() 为每个会话创建隔离的模型副本
  • 字段 metadata 的 clone: True 标记哪些模型需要独立状态

5. 模型接口层 (speech/interfaces.py, llm_agent/interfaces.py)

所有模型都通过抽象接口定义契约：

ASR 接口
方法 说明
recognize(audio: bytes) → str 单次识别 (必须实现)
recognize_stream(audio, is_final) → str 流式增量识别 (有默认实现)
reset() 重置状态
clone() 克隆实例
输入: PCM 16-bit mono 16kHz raw bytes
TTS 接口
方法 说明
synthesize(text) → bytes 文本转语音 (必须实现)
synthesize_stream(text) → Iterable[bytes] 流式合成 (可选)
set_voice(voice_names) 切换说话人
set_emotion(emotion) 切换情感
clone() 克隆实例
输出: PCM 16-bit mono 48kHz raw bytes
Agent 接口
方法 说明
`generate(input) → str \ (str, ToolCall[])`
`generate_stream(input) → Iterable[str \ ToolCall]`
clone() 克隆实例
add_tools(tools) 添加 Langchain 工具
输入支持 str 或 AgentInput(content, context)

核心数据流

用户语音 → [Frontend VAD] → WebSocket
            → InputGateway → AudioFrameReceived
            → EnhancerManager → EnhancedAudioFrameReceived
            → ASRManager → ASRResultPartial / ASRResultFinal
            → TurnTakingManager → TurnLLMAgentStartRequested
            → LLMAgentManager → LLMAgentResponseUpdate / LLMAgentResponseFinish
            → TurnTakingManager → TurnTTSStartRequested
            → TTSManager → TTSChunkGenerated
            → OutputGateway → WebSocket → 浏览器播放

中断流程:

用户再次说话 → VADSpeechStart
            → TurnTakingManager → TurnTTSStopRequested + TurnLLMAgentStopRequested
            → TTSManager 停止 / LLMAgentManager 停止
            → 新一轮 ASR 开始

扩展机制

添加新模型 (已有类型)

  1. 实现对应接口 (如 ASR, TTS)
  2. 通过 Xtalk.register_model_search_spec(slot, spec) 注册
  3. 在 JSON 配置中指定 type 和 params

添加新功能 (自定义 Service)

  1. 定义新模型类 (含 clone())
  2. 继承 DefaultPipeline，添加新字段
  3. 创建新 Manager，使用 @event_handler 装饰器订阅事件
  4. 可选: 使用 create_event_class() 创建新事件类型
  5. 使用 subscribe_event / unsubscribe_event 修改现有事件路由

配置驱动

JSON 配置直接映射到模型类名和构造参数：

{
            "asr": { "type": "SherpaOnnxASR", "params": { ... } },
            "llm_agent": { "type": "DefaultAgent", "params": { ... } },
            "tts": { "type": "IndexTTS", "params": { ... } }
        }

Slot 模型 部署方式

技术栈

  • 后端: 纯 Python 3.10+, FastAPI, asyncio, Langchain
  • 前端: Vanilla JS, WebSocket, AudioWorklet VAD
  • 通信: WebSocket (二进制音频 + JSON 信令)
  • 构建: setuptools + setuptools_scm
  • 代码规范: Black + Ruff + mypy
  • 测试: pytest
